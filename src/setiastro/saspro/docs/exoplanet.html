Variable Stars & Exoplanets

Full differential-photometry pipeline for variable-star monitoring and ground-based exoplanet transit detection — calibration, field tracking, ensemble photometry, Lomb-Scargle + BLS period search, phase folding, SIMBAD/VSX identification, and AAVSO-compliant export in single or multi-band form. (Formerly the Exoplanet Transit Detector.)

The amateur-to-professional bridge. This is the tool for a dark-sky amateur rig running differential photometry on candidate transit events and variable stars — the detection and vetting step whose output goes to professional databases, professional follow-up, or published papers where the final publication-grade fits are done in dedicated professional astronomy tools. Load a stack of light frames (raw or already-aligned), get differentially-calibrated light curves for every star in the field, run Lomb-Scargle and Box Least Squares to search for periodic signals, phase-fold candidate transits, identify the target via SIMBAD/VSX, and — the headline feature — export it all directly to AAVSO.
AAVSO integration — the bridge, out of the box. Export → AAVSO produces WebObs-compliant Extended Format files directly from your light curves. This is the signature feature of this tool: the mechanism by which amateur photometry contributes to professional databases of variable stars and exoplanet transits.

The implementation does the hard parts right: a three-tier photometric calibration cascade (ensemble zero point when ≥3 catalog comparisons are available, single-comparison fallback, check-star last resort), MAD-clipped sigma rejection to drop bad catalog magnitudes before they poison the zero point, APASS DR9 and UCAC4 catalog integration for Johnson B/V and Sloan r' (acting as R proxy, with honest NOTES annotation when it does), MAD-based SEM for the ZP uncertainty, systematic error floor added in quadrature (0.10 mag default, configurable), per-filter interleaved TB/TG/TR output for OSC (DSLR / color CMOS) data, and automatic MERR > 1.0 → "na" handling so a single out-of-range row doesn't bounce the whole file at upload. The full math and tier logic are in the Technical section (§18.15-18.17); the single-click workflow is in §15.

The publication-grade fits in the paper are done in dedicated professional astronomy tools; SASpro's job is bringing amateur data up to the quality bar where it's usable alongside those fits, and getting it there via AAVSO submission is the standard handoff.

Binning on load. Every frame — raw or calibrated — is software-binned the moment it's loaded. Auto (the default; Settings → Software binning) picks the factor from the stars on the first frame: 1×1 when they are under 3 px FWHM, otherwise the largest of 2–4 that keeps the binned FWHM at least 2.5 px. The WCS is tracked with a _wcs_bin_factor so pixel-to-sky conversions apply the correct scaling regardless of whether the WCS came from a header (full-resolution) or the solver (binned).

2. Loading frames

Both modes present a multi-select file picker (FITS, FIT, XISF, TIFF, TIF supported). A file picker shows one folder at a time, so for nights kept in separate folders load the first, then Load again: with frames already loaded you are asked whether to Add the new ones to them or Replace them. Files are read in parallel for header metadata, then sorted chronologically before loading pixel data. The time parsing hierarchy is:

  1. UT-OBS if present (already in UTC)
  2. DATE-OBS (treated as ISO-UTC; timezone offsets like -0700 are auto-normalized to -07:00)
  3. DATE-END as fallback
  4. MJD-OBS as the most robust final fallback

XISF files have their FITSKeywords block queried for the same keys. Any frame that fails to parse a time ends up at the end of the sort, after all time-stamped frames. The resulting ordered list drives everything downstream — the light curve x-axis, the reference frame selection, and the AAVSO JD field.

Each loaded frame also harvests two more fields:

  • Exposure time from EXPOSURE or EXPTIME. Needed for AAVSO export (per-frame integration).
  • Airmass from AIRMASS directly, or computed from altitude keys (OBJCTALT, ALT, ALTITUDE, EL) via X = 1/sin(h). Defaults to 1.0 if nothing is found.

How frames are loaded

  • In parallel. Frames are read, binned, checked for saturation and (without a GPU) star-detected in worker processes, one per core. SEP holds Python's GIL, so the old thread pool ran detection one frame at a time.
  • Software binning. Frames are averaged in b×b blocks as they load. Auto measures the stars on the first frame: 1×1 when they are under 3 px FWHM, otherwise the largest of 2–4 that keeps the binned FWHM at least 2.5 px. Raw colour mosaics always bin by an even factor. Binning does not raise photometric signal-to-noise — an aperture sums the same photons and read noise either way — but it divides memory and time by b² and costs nothing while stars stay a few pixels wide.
  • Off the heap. The binned frames go to a temporary file that every process maps, so a large set no longer has to fit in RAM. The file is created sparse — space is taken only as frames are written — and deleted when the window closes.
  • Startup work overlaps the file dialog. Starting the worker processes and the GPU takes 10–20 s the first time in a session. It begins when you click Load, while you pick the files, instead of freezing the window afterwards.
  • GPU star detection. With a CUDA, DirectML or MPS device, per-frame star catalogues (tracking and frame quality) come from the GPU detector as each frame arrives. SEP still measures the reference frame for the star list and the FWHM.
Which frames to load. Calibrated (dark + flat), unregistered frames are best: the tool tracks the field itself, so nothing needs to be resampled. Measured on NGC660, the author's own data set of 412 frames over 7 nights (Newtonian, ASI294MM). It is the real-data example quoted throughout this page; it is not distributed and you don't need it:
  • Calibrated and calibrated + normalised + registered frames gave the same comparison-star scatter, 5.8–5.9 ppt. A per-frame normalisation scale cancels in the differential ratio, and resampling costs little in a ~1.5×FWHM aperture.
  • Raw frames (no flat) were clearly worse: 14 ppt, with 80–190 ppt steps across a meridian flip, because every star moves across ~20% vignetting when the field turns.
The status line notes when raw or registered frames are loaded.

3. Calibration (Raw mode)

In Raw mode, two buttons let you load Master Dark and Master Flat files. Status labels flip from ❌ to ✅ when a master is successfully loaded. The dark and flat shapes must be compatible; mismatches surface as a warning and refuse the load. The masters are kept unbinned and binned to the frames' software bin when calibration runs.

Calibrate & Align Subs runs the full raw-to-aligned conversion on every loaded frame:

  1. Subtract master dark (if loaded).
  2. Divide by master flat (if loaded) via Numba-accelerated per-pixel division.
  3. Expand mono to RGB-equivalent if the input is 2D.
  4. Use the first processed frame as the reference, then astroalign-align every subsequent frame to it with an affine transform. See Stellar Alignment for the alignment engine details.

Save Aligned Frames writes the calibrated and aligned stack back to disk — useful if you want to inspect intermediate frames or feed them to a different downstream tool.

4. The Settings dialog (wrench icon)

The orange wrench button at top-right opens the full configuration panel, organized into three sections:

Photometry
• SEP detection σ (default 5.0) — threshold for star detection. Lower → more stars (including faint). Higher → only bright, well-detected sources.
• Border fraction (default 0.10) — fraction of each frame edge to exclude from detection. Stars within this border are dropped to avoid PSF truncation at frame edges and aperture-at-edge artifacts.
• Aperture radius (default Auto) — every star is measured at eight radii (0.75–3 × the median FWHM). Auto uses the radius that minimises the comparison stars' mutual scatter; or pin a multiple of the FWHM. The transit fit re-optimises the radius for its own target.
• Recentre apertures (default on) — apertures always follow the field from frame to frame; with this on, stars bright enough for a reliable centroid are also individually recentred.
• Camera gain (e-/ADU) (default Auto from EGAIN) — electrons per ADU at the gain setting you imaged with, read off the camera maker's gain chart (ZWO unity gain = 1.0); not the gain setting itself. It sets the stars' own shot noise in the error bars. It applies to calibrated float frames too, which are taken at SASpro's 0–1 = 0–65535 ADU scale. LCO/BANZAI frames (float, BUNIT = electron) are recognised automatically.
• Camera ADC (default Auto) — gain charts and EGAIN count the ADC's own steps, but a 12-bit ADC is written into a 16-bit file ×16 (14-bit: ×4), so the gain is divided by that factor. Auto reads it from raw 16-bit frames, where a 12-bit camera writes only multiples of 16. Calibrated or registered float frames can't show it, so set it by hand for those. Example: the ASI294MM is 12-bit unbinned (unlocked mode) and 14-bit at bin 2; on the NGC660 frames (unity gain, EGAIN 0.99) the sky noise measures ~0.06 e⁻ per file ADU, which is 0.99 ÷ 16. With the gain wrong, the error bars come out too small, and the per-frame noise measured from the comparison stars (§18.5b) and the fit's χ² scaling make up for it.
• Software binning (default Auto) — see §2.
• Use the GPU for star detection (default on) — see §2.

Ensemble Normalization
• Max comparison stars (default 10) — size of the weighted comparison ensemble. Candidates are the brightest unsaturated stars; each is weighted by its measured stability, variables are rejected, and the best k are kept.

Screening
• Flag only stars that stand out from the field (default on) — see §9.
• Field outlier threshold (default 5σ) — how many robust σ above stars of similar brightness a star's statistic must be.
• Flag night-to-night variability (long-period variables) (default off) — see §7.

Analysis (period search)
• LS samples / peak (default 10) — Lomb-Scargle frequency grid density.
• BLS min / max period (defaults 0.05 / 2.0 days) — period search range for Box Least Squares. The max is capped at 95% of the observational baseline internally.
• BLS # periods (default 1000) — number of periods in the search grid.
• BLS min / max duration fraction (defaults 0.01 / 0.5) — transit duration grid, as fraction of trial period.
• BLS # durations (default 20) — number of duration samples.

5. Measure & Photometry — the main pipeline

Once frames are loaded (and calibrated if raw), Measure & Photometry runs the full detection, aperture photometry, plate-solving, and ensemble normalization pipeline. In Calibrated mode, Load, Measure & Photometry combines the load and run into one click.

Progress updates stream in real-time. The pipeline:

  1. Pass 1: SEP detection on every frame in parallel (80% of CPU cores), with no-data (0.0) pixels masked. Records star count, FWHM and background per frame.
  2. Picks the best reference frame by quality metric (highest star count / FWHM / background).
  3. Plate-solves the reference frame to establish WCS. If a WCS already exists in the header, you're asked whether to use it or re-solve. XISF files always get re-solved because the embedded WCS is PixInsight's TPS approximation and can be off by 10-30" at frame corners.
  4. Filters the reference-frame SEP catalog to the interior (dropping stars within the border fraction).
  5. Tracking: an affine transform from the reference to every frame, matched on the star catalogs. The apertures follow the stars; frames are never resampled for photometry. Drift, small rotation and a 180° meridian flip are all handled; a frame that can't be matched is rejected and reported.
  6. Pass 2: aperture photometry of every star on every frame at eight radii, with a sigma-clipped annulus median sky and per-measurement flags for saturation, frame edge / no-data borders and bad sky.
  7. Weighted comparison ensemble with automatic rejection of variable comparison stars; frames where the comparison light collapses (cloud) are rejected; isolated outliers (cosmic rays, satellites) flagged.
  8. Stars unusable in more than half the frames (off the edge, in no-data borders) are dropped. Saturated stars are kept and tagged so a saturated target is reported rather than silently missing.
  9. For OSC color inputs, a per-channel R/G/B pass at the same tracked positions.
  10. Detrending and screening of every light curve (§8, §9), then the star list and overlay.
LCO and other observatory data. Rice-compressed .fits.fz files (BANZAI output) load directly. Times are mid-exposure from DATE-OBS/MJD-OBS + EXPTIME/2; the site comes from LATITUDE/LONGITUD/HEIGHT (or SITELAT/SITELONG and the other common spellings); SATURATE/MAXLIN mark saturated stars. Frames do not need to be pre-aligned.

7. The star list and light curve plot

Each detected star appears in the left-column list showing its index, x,y pixel position and its robust scatter σ in ppt. Tags: [COMP] — in the comparison ensemble; [SAT n%] — saturated in n% of frames; [DIP …] / [VAR] — flagged by the screening (§9). Click one or more entries (Ctrl-click to multi-select) and the right-side plot updates with the selected light curves in distinct colors. Drag the divider between the list and the plot to give either one more room; the split is remembered. A star named by Identify Star or Find Star (§10, §11) shows its name after its number.

The plot shows:

  • Points — the per-frame differential flux, detrended as selected.
  • Bins (5, 10, 15 or 30 minutes, or off; 5-frame bins without timestamps) — inverse-variance weighted means with their propagated error, scaled up when the points in a bin scatter more than their error bars allow.
  • For a single selected star: rejected measurements as red × (saturated, edge, bad frame, outlier), and the best detected dip shaded when the star is flagged. The title carries σ and the best dip's depth, significance and duration.

The x-axis shows hours since the first frame (mid-exposure UTC) when timestamps are available, or frame index when they aren't.

Graphical and Scientific plot styles

The Plot selector above the chart switches between two views of the same data:

  • Graphical — the interactive dark plot, built for browsing many stars quickly.
  • Scientific — a publication-style figure: white background, inward ticks on all four sides, serif type, every point with its ±1σ error bar, and binned points with error bars on top. The time axis is BJDTDB at mid-exposure when the field is plate-solved (JDUTC otherwise), with a whole-day offset in the label. With all nights shown (up to six), each night gets its own panel on a broken axis with a shared flux scale; longer campaigns use one continuous axis. Y switches between relative flux and differential magnitude (−2.5 log10 of the relative flux, brighter up). Several selected stars are stacked with vertical offsets listed in the legend instead of drawn on top of each other. The toolbar zooms and pans.

Save Plot… saves what is shown: the Scientific figure as a 300 dpi PNG, a PDF or an SVG (the vector formats keep text and axes sharp; the many unbinned points are rasterised to keep the file small), the Graphical plot as a PNG screenshot. The choice of style and bin width is remembered and shared with Fit Transit.

What the error bars mean

Each point's error bar combines two terms:

  • The CCD equation — photon noise of the target and the comparison ensemble, sky and read noise (§18.5). This needs the camera gain (§4); without it only the sky term is known.
  • Per-frame noise measured from the comparison stars — scintillation, thin cloud, seeing-driven aperture losses, flat-field errors as the field drifts. The CCD equation knows nothing about these, but the comparison stars show them frame by frame: in a frame where they scatter more than their own photon noise allows, every star in that frame gets the extra noise (§18.5b). A passing cloud or the high-airmass end of the night therefore shows larger error bars exactly where the data are worse.

Slow, correlated systematics are not part of a point's error bar; the transit fit handles them with the red-noise factor β (§18.9b).

7b. Data sets spanning several nights

Frames are grouped into observing nights: local noon to local noon from the site longitude in the headers (or, without one, split at gaps longer than 6 h), and separately per telescope, since an LCO sequence can hand off between sites with no daytime gap. Load every night's frames together, in one Load or with Add when the nights sit in different folders (§2); they don't need to be registered to one another, since every frame is tracked. When there is more than one night a Night selector appears next to Detrend:

  • All nights (default) — every night on one axis with the daytime gaps collapsed; dashed lines and dates mark each new night, and no line is drawn across a gap.
  • A single night — that night alone, hours since its first frame. The list's σ and flags, the overlay highlights and the status line all switch to that night.

Detrending is fitted over all nights at once and removes only what happens within each night (one airmass coefficient shared by every night, or per-night time terms); each night's level is fitted but never divided out, so a long-period variable's change from night to night survives. The screening gives each night its own level, so the step between two nights is never mistaken for a dip, and, with Settings → Screening → Flag night-to-night variability on, flags VAR night-to-night when a star's night levels vary well beyond the comparison stars' own night-to-night scatter. That test is for long-period variables (Miras, semiregulars) and is off by default: a transit happens within one night, and a flat-field residual that changes from night to night trips it too. On the NGC660 data 6 of the 18 stars along one edge of the frame were flagged that way, against 7 of the other 297. Variables flagged on any night stay out of the comparison and check stars. Analyze Star uses every night (each normalised to its own median for the BLS search); Fit Transit fits one night — it opens on the selected night, or on the night that covers the predicted transit once the planet is looked up.

Meridian flips

After a meridian flip the field is turned 180° on the sensor, so every star lands on a different part of it, and any flat-field or vignetting error turns into a per-star step in brightness. On the NGC660 data that step was 8–20 ppt with a flat and 80–190 ppt without one. Each frame's pier side is read from, in order:

  1. a PIERSIDE keyword;
  2. Sequence Generator Pro's FLIPPED keyword, when it changes within the set;
  3. the registration matrix SASpro writes into frames it registered;
  4. the tracked 180° rotation of the field.

Registered frames all face the same way, so tracking alone can't see the flip in them. Every (night, pier side) segment then gets its own level in the detrending, the dip search and the outlier test. The step is divided out, and each night's level is kept. A dip box must leave enough baseline in every segment it touches, so a box can't swallow a short segment and pass its level off as a dip. Fit Transit fits a flux step for the far pier side (fs) when the night contains a flip, which is AstroImageJ's meridian-flip offset. The status line says when a flip was found and how.

8. Detrending

The Detrend combo in the top-right offers four options. Changing it re-screens every star immediately.

  • No Detrend — differential flux as measured.
  • Linear — slow drifts across the night.
  • Quadratic — curvature as well. Can absorb part of a transit that sits mid-night; prefer Airmass or Linear when hunting transits.
  • Airmass (default) — a term in airmass, the physical shape of residual differential extinction (EXOTIC's systematics model). Falls back to Linear when the frames carry no airmass information.

Trends are fitted in time with iterative 3σ clipping and divided out; a trend that would go non-positive or swing by more than 2× is refused rather than applied. The detection statistics in §9 don't use the divided curve at all — the dip search fits the same baseline jointly with the dip.

9. Dip and variability detection

Every star's light curve is screened for two kinds of signal, and flagged when it clears both controls:

Min depth / amplitude (ppt) (default 5) — a DIP must be at least this deep; a VAR star's 10-minute-binned curve must span at least this much (5–95% range). Hot Jupiters are typically 5–25 ppt deep.
Min significance (σ) (default 7) — DIP: signal-to-noise of the best box-shaped dip, fitted jointly with the detrend baseline, against white noise plus the red noise measured at the dip's own duration. VAR: significance of smooth variability from the von Neumann ratio.

Relative to the field (on by default; Settings → Screening). Each star's dip significance, von Neumann statistic and amplitude are also compared with stars of similar brightness: the median and robust spread (1.4826 × MAD) of the same statistic among stars within ±0.5 mag, widened to at least 30 stars. A star is flagged only if it stands that many σ above them (default 5). DIP needs the dip significance to stand out; VAR needs both the von Neumann statistic and the amplitude to. This is the survey practice of Sokolovsky et al. (2017, the VaST study). Systematics shared by the whole field — seeing-dependent aperture loss, flat-field error, a meridian flip, thin cloud — raise every star's statistics together. A fixed cut then flags everything, which happened on real data before this: 281 of 321 stars flagged. The DIP entry shows how far above the field the star stands ("field +9σ").

One night at a time. With several nights loaded, the dip search runs on each night alone, with that night's own baseline and red noise, and All nights shows the best night's dip. A transit happens within one night, and one search across every night let the noisiest night's red noise set the bar for all of them. On NGC660 that turned a 40 ppt, 17.8σ dip into a diluted 2-hour box of 22 ppt at 6.6σ, so All nights and the single-night view showed different boxes.

Aperture test. Every dip candidate is re-measured at the largest aperture (3 × FWHM) against the same comparison stars. A real eclipse dims the whole star, so its depth is the same in any aperture. Light smeared out of the aperture by a change in the star's image — the telescope settling after a meridian flip, a focus shift, coma toward a corner — makes a "dip" that fades as the aperture grows. A dip whose depth at the large aperture is under half its depth at the photometry aperture, by more than 3σ, is withdrawn; the list shows it as dip ✗ PSF with both depths (hover over the entry for the explanation), and the plot title says so. A brighter neighbour inside the large aperture also dilutes a dip, so check blends by eye.

What this caught on NGC660. A 12th-magnitude star in a corner of the frame showed a clean 40 ppt, 25-minute dip that started on the first frame after a meridian flip. Its depth was 417 ppt at r = 3.7 px, 76 ppt at the 7.4 px photometry aperture and 7 ppt at 14.7 px, and its peak brightness fell by 45% while its total flux fell by 7%: the telescope settling after the flip, not a planet. The EW eclipsing binary in the same field measured 189, 188 and 185 ppt at the same radii. Two more stars along the same edge showed the same post-flip dip on three nights, and a star on the opposite edge did it just before each flip. All of them are withdrawn; on the 485 registered frames that leaves 4 flagged stars, three of them catalogued variables.

Stars usable in fewer than half the frames (saturated or off the edge most of the time) are not judged. A flagged star with a neighbour at least a quarter as bright within two aperture radii is tagged blend?: the apertures share light, and the share changes with seeing, which is a common source of false variability.

Flagged stars are highlighted yellow in the list and the overlay, with the dip depth and significance in the list entry; the status bar reports the counts.

Checked against known variables. On 412 NGC660 frames over 7 nights (Newtonian, ASI294MM), 13 of 315 stars were flagged on calibrated frames and 16 of 270 on calibrated + normalised + registered frames. Before these changes it was 281 of 321. Matched against VSX on a plate-solved WCS:
  • Both strong catalogued variables in the star list were flagged in both runs, each as DIP and VAR: an RRab (0.64 mag) and an EW eclipsing binary (0.23 mag).
  • So were the two 0.03 mag Gaia rotators that rise above the noise.
  • A saturated 8.8 mag δ Scuti was correctly kept out.
  • Five other 0.02–0.04 mag Gaia variables sit at the noise level and were not flagged.
  • Most of the remaining flags were night-to-night candidates on faint stars, many clustered along one edge of the frame. That is why the night-to-night test is now opt-in; with it off, the calibrated run flags 5 stars: the RRab, the EW, the 15.65 mag rotator, and two uncatalogued within-night dips.
Why red noise matters. Ground-based light curves wander on hour timescales (transparency, seeing, guiding). Judged against white noise alone, that wander produces "dips" at high nominal significance on stars that are perfectly constant. Charging every candidate dip with the correlated noise measured at its own duration (Pont et al. 2006) is what keeps the default 7σ meaningful. On simulated 4-hour, 2-minute-cadence curves with 2 ppt white plus correlated noise, about 0.7% of constant stars exceed 7σ, while 2-hour dips of 5 ppt or more are recovered every time.

10. Identify Star — SIMBAD / VSX lookup

Select exactly one star, click Identify Star…. The tool projects the star's pixel position through the WCS to RA/Dec, queries SIMBAD within 15" of that position, and returns the best match. For contested regions where multiple catalog entries fall nearby, a scoring system prefers:

  • Variable-star otypes (V*, Mi*, EB*, EA*, EW*, RR*, Ce*, dS*, SX*, Sr*, SR*, LP*, LPV, Ir*, Pu*, Ro*, RS*, BY*, Er*, FU*, TT*, Y*O, and more) — +100 to score
  • Named catalog designations (V*, V, NSV, HD, HR, HIP, TYC, BD, CD, ASAS, ASASSN, ZTF, OGLE, GSC, PPM, SAO, WDS, WISE) — +30
  • Generic Gaia designations (Gaia DR3, DR2, DR1, EDR3) — –30

Angular offset is subtracted from the score as a tiebreaker. If the best SIMBAD match still isn't flagged as variable, a VSX cone search within the same radius looks for a variable-star designation to upgrade to. The result dialog shows the ID, otype, V magnitude, and offset, with a one-click button to open the full SIMBAD page in your browser.

The name sticks. Once a star is identified, its name replaces "Star #N" in the plot titles and legends, the list, the Analyze Star window and Fit Transit, with the list number kept in brackets: CSS_J014208.2+135125 (#82). A match only names the star when it lies within 5″ of it; the lookup prefers a variable anywhere within 15″, and that can be a neighbour. The Gaia DR3 fallback names it when the Gaia source is within 3″. Find Star (§11) names the star it selects with the name you typed. Names last until the next Load & Measure, which numbers the stars afresh.

11. Find Star by name

The reverse operation: enter any SIMBAD-resolvable name (e.g. "V336 Aps", "HD 12345", "TYC 9256-617-1", "Gaia DR3 ...") and the tool resolves the name to RA/Dec, projects back through the WCS to detector pixel coordinates, and selects the nearest detected star in the list.

The matching tolerance adapts to the data: it's the maximum of 2× the median FWHM in detector pixels, 10 arcseconds converted to detector pixels using the WCS plate scale, and a 6-pixel floor. If no star is within tolerance, you get a specific diagnostic — "resolves to pixel (X,Y) but closest detected star is N pixels away" — so you know whether SEP dropped the star (faint, border, saturated) or the target isn't in frame at all.

When CDS is down. Every lookup fails over across mirrors through SASpro's shared CDS health check (the same one WIMI, SFCC and the Magnitude tool use). Find Star tries SIMBAD on each mirror (Strasbourg, Harvard, IDIA), then Sesame name resolution on cds.unistra.fr and the VizieR mirrors. Identify Star tries SIMBAD, then SIMBAD's TAP endpoints directly, then VSX. If none of them names the star, it reports the nearest Gaia DR3 source — from the local Gaia library the plate solver uses (offline, instant), else from Gaia DR3 on the VizieR mirrors — with its G magnitude and offset, and says whether SIMBAD was unreachable or simply has no entry. Most field stars are not in SIMBAD at all, and the Gaia offset also confirms the plate solution put the star in the right place. VSX, APASS, UCAC4 and the limb-darkening tables come from whichever VizieR mirror is answering (Strasbourg, CfA, IDIA, NAOJ, …), and a mirror that answers a catalog lookup with no rows is passed over for one that has them. For the AAVSO check star, the nearest UCAC4 star (with its APASS V) stands in when SIMBAD can't name one. Settings → CDS / SIMBAD → Test now shows which mirrors are answering.

A single transit. This is the usual case: one dip, then the hunt for the next one weeks, months or years later. Analyze reports it as a result. Tc, depth and T14 are the measurement. The period is not: with one transit, the BLS period is just one of the periods the other nights don't rule out, so the summary says so.

Box versus transit model. BLS fits a box: the flux drops instantly, stays flat and comes straight back up. That is how it finds the period quickly, but it isn't the shape of a transit. On the fold, Analyze fits the transit model Fit Transit and EXOTIC use, at the BLS period. The planet's disc takes time to cross the edge of the star, so ingress and egress are slopes; limb darkening rounds the floor; and the model is averaged over each exposure. Before the fit, the systematics (airmass, per-night levels, the pier-side step) are refitted with the transit frames masked, so the baseline can't absorb part of the dip, and every night is set to its out-of-transit median. Limb darkening is fixed at u1 0.465, u2 0.257. For a published transit time use Fit Transit, which also runs the MCMC; the fold is for judging the candidate.

Warnings (orange). Analyze warns about three things:

  • Odd and even transits differ by more than 3σ: alternating depths. That is the signature of an eclipsing binary found at half its period, whose primary and secondary eclipses fall on alternate epochs. It can also mean the period is wrong and one set of "transits" isn't a dip at all. The test needs at least one transit of each parity.
  • The aperture test fails (§9): each transit is checked, and one that fades in a bigger aperture is a PSF change. On NGC660 the post-flip dip of #20 folds into a smooth, 18σ "transit" at 0.265 d, from one night. Its depth falls from 62 to −2 ppt between the 7.4 and 14.7 px apertures.
  • Deep or V-shaped (Rp/R* ≥ 0.3 or b ≥ 0.9): this is typical of an eclipsing binary. Look at 2 × P, since a W UMa's two eclipses fold onto one.

Several nights. The BLS period grid has to get finer as the data span grows: its step is the shortest trial duration divided by the span squared. That's about 3,500 trial periods for one night, but 28 million for seven nights spread over 27 days, which would take more than a day to compute. Analyze scans at most 100,000 periods, then re-scans each of the strongest peaks at the full resolution. The scan runs on all CPU cores, and a long one shows its progress with a Cancel button. On the 7-night NGC660 data it takes about 17 s. The W UMa binary CSS_J014208.2+135125 (VSX period 0.31167 d) comes out at 0.15583 d, half its period. That is the expected BLS result for an eclipsing binary with two nearly equal eclipses per orbit.

Reading the SDE. Signal Detection Efficiency: how many sigma above the noise floor the BLS peak sits, after whitening. SDE > 7 is a strong candidate; 5-7 is marginal (worth phase-folding to inspect); below 5 is noise-dominated. The reported SDE already has the alias penalty subtracted — alias-contaminated peaks near 0.5, 1.0, 2.0, or 3.0 days get downweighted so true planetary signals win over nightly-cadence artifacts.

Select the host star, click Fit Transit…. This is the workflow of NASA JPL's Exoplanet Watch pipeline EXOTIC, implemented independently inside SASpro:

  1. Priors. If the frames are plate-solved, known planets at the star's position are looked up automatically in the NASA Exoplanet Archive; or type a planet/host name and Look up. Period, reference Tc, Rp/R*, a/R*, inclination and eccentricity are filled in with their uncertainties, along with the predicted mid-transit time for this night. Everything stays editable.
  2. Limb darkening. Quadratic coefficients from Claret & Bloemen (2011) for the star's Teff / log g / [Fe/H] and the filter (read from the FILTER keyword; LCO names like rp are recognised). Clear and broadband exoplanet filters map to the nearest standard band, marked approximate.
  3. Selection. Every aperture radius × a family of comparison sets (the weighted ensemble, its best-n subsets, and each of the best single comparisons) is fitted by least squares, and the combination with the lowest residual scatter wins — EXOTIC's selection metric.
  4. Fit. Transit × systematics, with Tc, Rp/R* and (by default) inclination free. Systematics default to Auto: every model (none, EXOTIC's airmass term a1·exp(a2·X), linear or quadratic in time, airmass + linear) is fitted, and the lowest BIC wins (§18.9b). Any model can also be picked by hand. Airmass alone can't follow a steady drift through the night: when the run is centred on the meridian, airmass is U-shaped in time. Outliers are clipped against their neighbours. Posteriors come from an affine-invariant ensemble MCMC; the photometric errors are first scaled by √χ²red (only ever inflated) and by the red-noise factor β.
  5. Results. Tc in BJD_TDB with its uncertainty, O–C against the ephemeris, Rp/R*, depth, impact parameter, T14, airmass coefficients, residual RMS per point and per 10 minutes, β, and which aperture and comparison set were used.

Produces an AAVSO Extended Format text file ready for WebObs submission. This is where the tool stops being an analysis plaything and starts producing data someone else can use. Two export paths:

Single-band export

For mono data or when you want one filter at a time. The flow:

  1. Select one target star in the list.
  2. Target name auto-resolved via SIMBAD/VSX (editable).
  3. AAVSO observer code (persisted across sessions).
  4. Submission format. Exoplanet Report opens the Transit Fit window (§13b) — the exoplanet report is written from a fit.

Multi-band export (OSC color data)

Measurements the photometry rejected (saturated, edge, rejected frames, outliers) are excluded from the zero point and the reported rows.

When OSC per-channel photometry is available, you're offered a one-click option to export all three channels interleaved in a single AAVSO Extended file: TB (Blue), TG (Green standardized to V), TR (Red). This is the biggest workflow win for DSLR / OSC observers: one upload, three bands, standardized against catalog B / V / R magnitudes.

For each band, the calibration pipeline tries three tiers in order:

  1. Ensemble zero point (preferred) — requires ≥3 comparison stars with catalog magnitudes in that band. Computes ZP(t) = mediani(Vcat,i + 2.5 log10 Fi(t)) per frame with MAD-based 3σ clipping. Delivers a proper AAVSO ENSEMBLE entry.
  2. Single-comparison — when only 1-2 catalog comparisons are available in that band. Picks the brightest of them for best SNR and does classic differential photometry.
  3. Check-star fallback — last resort when no catalog comparisons exist in that band. The check star doubles as the comparison; AAVSO can still accept the row but the CMAG and KMAG fields reflect that compromise.

Catalogs are tried in order: MagTool cache (if available from a prior Magnitude Tool session on this frame), APASS DR9 (Johnson V/B + Sloan r'), UCAC4 (same with slightly different coverage). When Sloan r' is used as the R anchor, the NOTES field includes "R anchor = Sloan r' (APASS/UCAC)" so a reviewer knows exactly what was done.

MERR > 1.0 handling. AAVSO Extended Format rejects any row with MERR > 1.0 at upload — the whole file bounces. When a frame produces a valid MAG but an uncertainty outside this limit, the tool emits MERR=na rather than dropping the row entirely. The summary dialog at export completion reports the count per filter so you know how many rows got the na-flag treatment.

18. Technical details

Star detection, aperture photometry, ensemble normalization, the period search algorithms, the AAVSO calibration tiers, and the plate-solve integration.

18.1 SEP detection pipeline

Every frame is run through SEP (Barbary 2016, port of SExtractor by Bertin & Arnouts 1996) in parallel across a thread pool sized to 80% of available CPU cores. Per frame:

  1. No-data (0.0) and non-finite pixels masked.
  2. SEP background map and global RMS computed on the masked frame.
  3. Source extraction with the user's σ threshold (default 5.0), minarea 9, deblending threshold 32; catalog sorted brightest first.
  4. Per-source FWHM via FWHM = 2.3548 · √(a·b) from SEP's semi-axis measurements:
\mathrm{FWHM} = 2.3548 \cdot \sqrt{a \cdot b}

And ellipticity:

e = \sqrt{1 - (b/a)^2}

Per-frame stats recorded: star count, mean level, and the median FWHM of the brighter half of the unflagged detections.

18.2 Reference frame selection

The best reference frame is chosen by a quality metric:

Q_i = \frac{N_{\mathrm{stars}}}{\mathrm{FWHM} \cdot \langle I \rangle}

which rewards frames with many detections, small PSFs, and low background. The frame with highest Q becomes the detection template for the rest of the pipeline — its SEP catalog defines which stars get photometered, its WCS gets plate-solved, and its star positions are carried onto every other frame by the tracking transform (§18.4).

18.3 Plate-solving integration

The reference frame goes to the plate solver. Three paths:

  • Existing WCS in header, non-XISF, not forcing → user asked whether to use the header WCS (fast) or re-solve (fresh). Default is "yes, use it".
  • XISF source → always re-solve. The XISF format embeds a TPS (thin-plate spline) WCS approximation computed by PixInsight that can be off by 10-30 arcseconds at frame corners — too imprecise for star-matching tolerances. SIP and CD/CDELT headers are stripped from the seed, keeping only CRVAL / OBJCTRA / OBJCTDEC / FOCALLEN / XPIXSZ as hints.
  • Header WCS synthesised from the mount pointing (SASpro's SASWCSSY marker, or a reference point identical to the mount's RA/DEC with no solver keywords) → plate-solved without asking. Such a WCS is arcminutes off: on the NGC660 frames it put stars ~190" from their catalogue positions, which names the wrong star in VSX/SIMBAD and pulls the wrong comparison magnitudes. If the solve fails it is still used, with a warning, because it is good enough for BJD and airmass.
  • Force blind solve enabled or no existing WCS → straight plate solve from scratch.

The _wcs_bin_factor is tracked throughout: a header WCS is full-resolution (so bin_factor = the software bin when applied to our binned coordinates), solver WCS is already in binned coordinates (so bin_factor = 1). Every pixel-to-sky conversion downstream respects this.

18.4 Tracking

For every frame, an affine transform from reference to frame pixels is estimated from the two SEP catalogs (brightest 60 stars): every reference–frame star pair votes for an offset, the densest offset bin wins, stars are matched within 1.5 × FWHM, and an affine is fitted to the matches by least squares with 3σ clipping. If the vote fails, the same is tried with a 180° rotation (meridian flip), then astroalign on the catalogs. A frame that can't be matched is rejected for every star.

Bright stars (centroid SNR ≥ 15) are additionally recentred with an iterative flux-weighted centroid inside 1.2 × FWHM, accepted only if it stays within 1 FWHM of the prediction. Fainter stars use the transform's prediction, which — fitted on dozens of stars — is better than their own noisy centroid.

Before this, every frame was measured at the reference positions. Any drift walked stars out of their apertures at different times, which is how a light curve ends up swinging between zero and several times its median.

18.5 Apertures, sky and errors

Radii rk = mk · FWHM with m ∈ {0.75, 1, 1.25, 1.5, 1.75, 2, 2.5, 3} (EXOTIC searches 1.5–6 Gaussian σ, the same range), minimum 1.5 px, fixed across frames. The annulus starts 2 px (or 0.5 FWHM) beyond the largest aperture and is at least 5 px wide.

Sky is the median of the annulus pixels after iterative 3σ clipping (stars and cosmic rays in the annulus are clipped out); no-data pixels never enter it. The aperture sum uses exact pixel overlap (SEP, subpix = 0):

F = \sum_{\mathrm{ap}} I - A\,\tilde{s}, \qquad \sigma_F^2 = \frac{F}{g} + A\,\sigma_s^2\left(1 + \frac{A}{n_s}\right)

with A the aperture area, s̃ and σs the sky median and robust scatter, ns the number of sky pixels and g the gain in electrons per data unit (§4).

Saturation. Saturated pixels are located on the unbinned frame, since binning averages a clipped core away. A measurement whose aperture contains one is flagged, and a star saturated in any frame can't be a comparison star. The level comes from MAXLIN / SATURATE, or from a plateau of pixels sharing the frame maximum (raw data). Calibrated, normalised or registered frames have neither: a clipped core sits at (full well − dark) / flat, which varies across the field with the flat. For those, the flat-topped star cores themselves are found: several pixels within 0.3% of a core's maximum, which an unsaturated PSF can't produce. The level is set 10% under the lowest of them, because CMOS response is already non-linear there. Before this, flat-fielded frames reported no saturation at all. On NGC660 every comparison star was then saturated, and almost every star in the field was flagged variable.

18.5b Per-frame noise from the comparison stars

Model: in frame j every star carries an extra fractional variance sj2 beyond the CCD equation, independent from star to star. A transparency change common to the whole field cancels in the differential and never appears. For each comparison star's leave-one-out curve r, the second difference dj = rj − (rj−1 + rj+1)/2 removes slow trends (colour-dependent extinction, a slowly varying comparison) and has variance

\mathrm{Var}(d_j) = V_{\mathrm{ccd}} + 1.5\, s_j^2 (1 + q), \qquad q = \frac{\sum w_k^2}{(\sum w_k)^2}

over the other comparison stars (their averaged excess). sj2 ≥ 0 is solved so that the median of d2/Var(d) over the comparison stars in a 5-frame window equals the median of a χ²1 variable (0.455). Because it is a median, one variable comparison star or one cosmic ray can't set it. Windows never cross from one night into the next. A star's relative-flux error then becomes

\sigma^2 = \sigma_{\mathrm{ccd}}^2 + f^2 s_j^2 (1 + q)

— its own excess plus the weighted ensemble's. The AAVSO magnitude errors add the same term (×2 in the single-comparison fallback). Binned points use the inverse-variance weighted mean, with error 1/√Σw scaled by √χ²red of the bin when that exceeds 1.

Synthetic check (simulated data only): a field with photon noise plus per-star scintillation that grows with airmass and a cloudy stretch, gain known. Normalised residuals of constant stars came out at std 0.97–1.15 in clear, cloudy and high-airmass stretches with these errors, against 1.3–2.5 with the CCD equation alone. With the gain unknown (no Poisson term), they improved from 10–24 to 1.2–1.5. The remaining excess is brightness-dependent noise that a single fractional term can't fully represent, and the transit fit's χ² scaling absorbs it.

18.6 Weighted comparison ensemble

Candidates are the brightest stars that are never saturated and usable in ≥ 90% of frames. Each comparison j is normalised to its own median, fj, and weighted by the inverse variance of its scatter against the ensemble of the other comparisons (Broeg, Fernández & Neuhäuser 2005):

A(t) = \frac{\sum_j w_j f_j(t)}{\sum_j w_j}, \qquad w_j = \sigma_j^{-2}, \quad \sigma_j = \sigma_{\mathrm{rob}}\!\left[\frac{f_j}{A_{-j}}\right]

Comparisons whose scatter is far in excess of their photometric error (variables, blends, stars on a bad column) are rejected and the weights recomputed until the set settles; the best k are kept. Every star's differential flux is f(t)/A(t), with A−i (leave-one-out) for comparison stars. Frames where A(t) < 0.25 (heavy cloud) or most comparisons are unusable are rejected.

18.7 Detrending

Least-squares fit of the chosen baseline (constant, linear or quadratic in time, or linear in airmass) with iterative 3σ clipping, divided out, re-normalised to unit median. Refused if the trend would leave [0.5, 2] over the data.

18.8 Measurement flags

Each (star, frame) carries a bit mask: edge / no-data in the aperture (1), saturated pixel within the largest aperture (2) — located on the unbinned frame from MAXLIN/SATURATE or a clipped-ADC plateau, since binning averages a clipped core away — rejected frame (4), isolated outlier (8), invalid flux (16), bad sky (32). Outliers are points more than 5σ from the median of their two neighbours on each side: a linear ramp such as ingress has zero residual against that median, so steep eclipse branches are never clipped.

18.9 Detection statistics

Box search. For trial durations D from 0.5 to 5 h and centres across the night, the model y = B·c + δ·box is solved by least squares (B = the detrend baseline), all trials at once from cumulative sums. The best box per duration is re-scored with red noise measured on the residuals of that model (box included, so a real dip does not inflate its own noise):

\mathrm{SNR} = \frac{-\delta}{\sqrt{\sigma_w^2\,(G^{-1})_{\delta\delta} + \sigma_r^2(D)}}, \qquad \sigma_r^2(D) = \max\!\left(0,\; \sigma_{\mathrm{bin}}^2(D) - \frac{\sigma_w^2}{N_D}\right)

σw is the point-to-point (white) noise and σbin(D) the RMS of the residuals averaged in bins of length D (Pont, Zucker & Queloz 2006).

Variability. The von Neumann ratio η = δ²/s² of the baseline residuals is ≈ 2 for white noise and falls toward 0 for smooth variability; its significance is z = (2 − η)·√N / 2.

18.9b Transit model and fit

The model is a quadratic limb-darkened star occulted by an opaque disc, I(μ) = 1 − u1(1 − μ) − u2(1 − μ)², integrated over the occulted arcs with end-clustered Gauss–Legendre quadrature (exact to 4·10−13 for a uniform disc; agrees with brute-force 2-D integration to the grid's resolution). Circular or eccentric orbits (Kepler's equation solved per point); the model is averaged over the exposure when an exposure is a significant fraction of ingress. Systematics multiply the transit:

F(t) = T(t)\; c_0\, e^{a_2 (X - X_0)}\,(1 + c_1\tau + c_2\tau^2)

reported in EXOTIC's convention a1 = c0e−a2X0. Starting point: a Tc grid scan, then bounded least squares. Priors: Tc uniform within max(10σpred, ½T14, 1 h) of the prediction; Rp/R* uniform; inclination within ±5° (Gaussian if the archive gives an error); a/R* fixed or Gaussian; b < 1 + Rp/R*. Errors are scaled by √χ²red (never down) and by the time-averaging red-noise factor β (Winn et al. 2008, bins of 10–30 min), then the posterior is sampled with the Goodman & Weare (2010) affine-invariant ensemble sampler; medians and 16/84th percentiles are reported.

Automatic systematics. Before the full fit, each systematics model (none, airmass, linear, airmass + linear, quadratic) gets a least-squares transit fit on the same points. A point that is an outlier under any model is left out of all of them, so the χ² values compare. The model is chosen by

\mathrm{BIC} = \chi^2/s^2 + k \ln n

the criterion AstroImageJ uses for its detrend parameters. k is the number of free parameters, and s² scales the errors so the most flexible model has χ²red = 1 (never scaled down). With red noise the photometric errors are too small, and every extra term would otherwise look significant. Within ΔBIC 2 of the lowest, the model with the fewest terms wins: a term has to earn its place. Time trends are only offered when there's out-of-transit baseline on both sides of the transit (at least max(5, 10% of the points) each). With baseline on one side only, a slope trades against the depth. The summary lists every model's ΔBIC and marks the winner. If the winner isn't airmass, the AAVSO report's notes name the model; DETREND_2 is the fitted systematics in every case.

Synthetic check (simulated only), on a night shaped like a WASP-12 b observation: −4 to +5 h around the transit, 4-min cadence, 2.2 ppt noise, meridian-centred airmass, 20 noise draws per case. A flat baseline chose none 20/20 times; an airmass extinction term chose airmass 20/20; a 4 ppt linear drift chose linear 20/20. On that drifting night the airmass-only fit put Tc 1.4 min early on average, with 58% of the true Tc values inside its 1σ errors. Auto put it 0.1 min early, with 92% inside 1σ (12 draws). Runs ending mid-transit never got a time trend.

18.10 Lomb-Scargle periodogram

Frequency grid from 1/baseline to Nyquist:

\nu \in [1/T_{\mathrm{span}},\; 0.5/\Delta t]

Via astropy's LombScargle.autopower with configurable samples-per-peak density (default 10). Peak period marked on the display. Best for sinusoidal variability — pulsators, eclipsing binaries at frequency-doubled signatures, rotational signals.

18.11 BLS pipeline with whitening and alias penalties

Box Least Squares is where the real transit search happens. The pipeline:

  1. Clean light curve: sort, positive-only, median-normalize, 6σ upper-outlier clip, re-normalize.
  2. Duration grid: linear spacing between min and max duration fractions of the minimum period:
d \in [d_{\min}\, p_{\min},\; d_{\max}\, p_{\min}]
  1. BLS with SNR objective, 10× oversampling, on a grid uniform in frequency with step dmin / Tspan², capped at 100,000 periods (see §13, "Several nights").
  2. Whiten the raw power spectrum by subtracting a running median:
P_w(T) = P(T) - \mathrm{medfilt}(P(T),\, w)

This removes slow trends in the periodogram baseline that would otherwise dominate SDE calculations.

  1. Find the top 12 local maxima in the whitened spectrum. Peaks within 1% of each other in period are merged (same signal at different grid points).
  2. For each candidate peak, do a local refinement BLS on a dense grid ±20% around that peak, picking the best SNR point. When the cap applied, the refinement covers ±1.5 coarse steps around the peak at the full resolution, measured against the coarse spectrum's background so the SDEs stay comparable.
  3. Compute SDE for each refined candidate:
\mathrm{SDE} = \frac{P_w - \mathrm{median}(P_w)}{\sigma_{\mathrm{MAD}}(P_w)}
  1. Compute the alias penalty — downweighting periods near 0.5, 1.0, 2.0, 3.0 days (the diurnal cadence aliases that plague ground-based observing):
\pi_{\mathrm{alias}} = \max_{a \in \{0.5, 1, 2, 3\}} \max\left(0,\; 1 - \frac{|P/a - 1|}{\tau}\right)

with tolerance τ = 0.02 (within 2% of an alias).

  1. Final adjusted SDE:
\mathrm{SDE}_{\mathrm{adj}} = \mathrm{SDE} - 1.5 \cdot \pi_{\mathrm{alias}}

The best SDE_adj across all candidates wins. This is the design that prevents the "every ground-based BLS peaks at 1.0 day" problem — a true planetary signal at some real period beats a 1-day sidereal alias even if the raw BLS power at 1.0 day happens to be slightly higher.

18.12 Phase folding and binned curves

At the chosen period P and epoch t0, fold to [-0.5, +0.5]:

\phi = \left(\frac{t - t_0}{P} + 0.5\right) \,\mathrm{mod}\, 1 - 0.5

The plot is in hours from mid-transit, φ·P·24, with the fitted Tc as the epoch. The data come from the raw target/ensemble ratio:

  1. Frames within 0.75 × the box duration of a predicted mid-transit are masked. The within-night systematics (§18.7) are then refitted on the remaining frames. A baseline level is only ever fitted from out-of-transit frames; fitting a level to transit frames erased a 48 ppt eclipse in testing. So:
    • A night with fewer than 5 out-of-transit frames has no baseline and is left out.
    • When the meridian flip falls inside the transit, one pier side can be left with fewer than 5 out-of-transit frames. That night is treated as one segment, and its far-side frames are divided by the flip step. The step is the median ratio between the two sides, measured on the nights that have at least 5 out-of-transit frames on each side.
    • If no night gives a flip step, that side's frames are left out.
    The summary lists what was left out or corrected.
  2. Each night is divided by the median of its out-of-transit frames.
  3. A quadratic limb-darkened transit (§18.9b), averaged over the exposure, is fitted by bounded least squares, starting from a Tc grid scan. Tc, Rp/R*, a/R*, inclination (60–90°) and a level are free; P is fixed at the BLS period and u1, u2 at the Fit Transit defaults. A 4σ neighbour-median clip is followed by a refit. The errors quoted are from the least-squares covariance, scaled by √χ²red when the scatter exceeds the photometric errors.
  4. Steps 1–3 are repeated once, with the mask set to ±(T14/2 + max(T14/4, 10 min)) from the fit. A box shorter than the transit otherwise leaves the ingress and egress in the "baseline".
  5. The model's significance is √(Δχ²/χ²red), where Δχ² is the χ² of a flat line minus that of the model.

Odd/even test (the Kepler vetting test). Every transit epoch with at least 3 points in transit counts. The fitted shape s(t) = 1 − T(t) is kept, and only a depth scale is fitted, separately for each transit. This is linear least squares, a = Σw(1−y)s / Σws², so partial transits count.

  • Errors: each transit's error is multiplied by √χ²red and by the red-noise β (§18.9). Both are measured on residuals with each parity at its own depth, so the difference being tested doesn't count as noise. β uses bins of ¼ to 1 × T14, because a depth averages over the whole transit and 10–30 min bins understate its error.
  • Combining: odd and even transits are each combined into a weighted mean. Both errors are then multiplied by the Birge ratio √(χ²/dof) of the transits about their own parity's mean, with dof = transits − 2. So the errors are as large as transits of the same parity actually scatter.
  • Warning: |aodd − aeven| above 3σ is flagged.

Synthetic check, injected into three quiet NGC660 stars on the real timestamps, folded at half the binary's period:

  • 48 / 30 ppt binary: flagged at 4.4–10σ on all three stars.
  • 48 / 44 ppt binary: 3.2σ on the quietest star, 1.4–2.4σ on the others.
  • Equal 48 / 48 ppt binary: 0.4–1.7σ, never flagged.
  • 13 ppt planet: 0.3–2.2σ, never flagged.

Bins are 10 minutes. For a transit shorter than 50 minutes they shrink to T14/5, but never below two exposures. Each bin is the inverse-variance mean with its propagated error, inflated when the bin scatters more than its errors (the Fit Transit binning). The BLS box is drawn dashed, centred where BLS put it. If the fit finds no transit (b ≥ 1 + Rp/R*, or Rp/R* < 0.003), the fold shows the BLS input and the box only, and says so.

18.13 Night dip event detection

Independent of BLS, a per-night dip detector segments the light curve by observational gaps (default > 0.2 days):

\delta = \mathrm{OOT} - \min(\mathrm{smooth}(f))

where OOT is out-of-transit (segment median of the smoothed curve). Required to be > max(2σsegment, 0.0008). Transit-shaped dips (down then up) get event entries. Reports per-event center time, depth, SNR, and duration. The summary line in the Analyze window reports the count — if your "candidate" shows 0 night-dip events but has a strong BLS peak, that peak is probably an alias; if it shows 5 events across 5 nights at consistent timing, you've got something real.

18.14 Multi-band R/G/B photometry (OSC inputs)

For color inputs, a secondary photometry pass runs the same measurement (tracked per-frame positions, the chosen aperture radius, clipped annulus sky, flags) on each R, G, B channel separately; flagged measurements are left empty. A "color" set whose three channels are identical is mono stored as RGB and is treated as mono. The result is a 3D array raw_flux_rgb shaped (3, n_stars, n_frames) with corresponding errors. Both are set to None when the input is mono, and the AAVSO exporter falls through to single-band mode.

18.15 AAVSO calibration — ensemble zero point

When ≥3 comparison stars have catalog magnitudes in the target band, compute a per-frame ensemble zero point:

\mathrm{ZP}(t) = \mathrm{median}_i\{V_{\mathrm{cat},i} + 2.5 \log_{10} F_i(t)\}

Target magnitude:

m_T(t) = -2.5 \log_{10} F_T(t) + \mathrm{ZP}(t)

The comparison set is first MAD-clipped (robust 3σ on each star's run-median ZP, with a 0.05 mag floor to prevent over-clipping tight ensembles): comparison stars with discrepant catalog magnitudes get dropped before the per-frame ZP is computed. SEM per frame:

\mathrm{SEM} = \frac{1.4826 \cdot \mathrm{MAD}}{\sqrt{N}}

Final MERR combines target instrumental uncertainty, ZP SEM, and a systematic floor:

\sigma_m = \sqrt{\left(\frac{2.5}{\ln 10} \cdot \frac{\sigma_F}{F}\right)^2 + \mathrm{SEM}^2 + \sigma_{\mathrm{floor}}^2}

Default floor is 0.10 magnitudes — a defensive estimate of unmodeled systematics (color terms, atmospheric variations, aperture scatter). Can be reduced to 0.05 or 0.0 if you've characterized your rig and know your actual systematic contribution. The ensemble zero point approach is standard practice for professional transit surveys and gives photometric accuracy within 0.01-0.03 magnitudes under good conditions, limited mainly by catalog magnitude accuracy.

18.16 AAVSO calibration — single-comparison fallback

When only 1-2 comparison stars have catalog magnitudes, pick the brightest (highest median flux — best SNR, most stable anchor):

m_T(t) = c_mag - 2.5·log10(F_T(t) / F_C(t))

Error propagated through both flux measurements plus systematic floor. The AAVSO row's CNAME field points at the chosen comparison; KMAG field holds the independent check-star value for post-upload sanity checking.

18.17 AAVSO calibration — check-star fallback

Last resort when no comparison stars have catalog magnitudes in the target band. The check star doubles as the comparison. CNAME points at the check star, KMAG field is "na" because there's no independent check anymore. The NOTES field documents the tier used so a reviewer can see exactly what was done.

18.18 SIMBAD / VSX name resolution scoring

Variable-star otype prefixes get +100 to the match score:

V*, Mi*, EB*, EA*, EW*, RR*, Ce*, dS*, SX*, Sr*, SR*, LP*, LPV, Ir*, IR*, Pu*, Ro*, RS*, BY*, Er*, FU*, GC*, Ta*, TT*, Y*O

Named catalog designations get +30:

V*, V, NSV, HD, HR, HIP, TYC, BD, CD, ASAS, ASASSN, ZTF, OGLE, GSC, PPM, SAO, WDS, WISE

Generic Gaia designations get -30:

Gaia DR3, Gaia DR2, Gaia DR1, Gaia EDR3

Angular offset is subtracted (closer wins). This solves a real problem: without scoring, SIMBAD's "nearest match" would often return a Gaia DR3 identifier for a star that's actually catalogued as, say, V336 Aps — Gaia has an entry for literally everything, and a plain nearest-neighbor return pollutes the exported #NAME field. The scoring plus the VSX fallback produces the right answer (the variable-star designation) when one exists.

18.19 Thread parallelism

Both SEP detection (pass 1) and aperture photometry (pass 2) run in parallel across a thread pool sized to 80% of available CPU cores. SEP itself is single-threaded internally so this gives real linear speedup. Per-frame tasks are completely independent (no shared state), so there's no lock contention. On an 8-core machine, a 200-frame session processes in roughly the time it takes one frame × 32 — a 6× speedup over serial execution.
