Survey Reference Gradient Correction — SRGC

Removes the part of your background that the real sky does not explain. SRGC fetches an image of your exact field from a published survey — or uses a frame from your own second scope — models both backgrounds on the same sample points, and subtracts only the residual. Real nebulosity survives because it is present in the reference too. Requires a plate solution; the survey path also needs a network connection. Non-destructive: nothing changes until Apply.

1. Why this exists

ADBE models your background and removes it. The problem it cannot solve is attribution. Your background is

B_t(x,y) = s\,S(x,y) + G(x,y) + c

where \(S\) is real diffuse sky structure — nebulosity, IFN, galactic cirrus — and \(G\) is your gradient: light pollution, airglow, a vignetting residual, moonlight. A self-contained model sees one surface and has no way to tell those apart, so it removes some of each. That is why large faint structure quietly flattens out, and it is the reason PixInsight funded an entire survey (MARS) to attack the same problem.

SRGC breaks the degeneracy with outside information. It fetches a reference image of the same patch of sky, models its background the same way, and fits

B_t \approx a + b\,B_r

robustly across the frame. Whatever is left over,

G = B_t - (a + b\,B_r)

is the part of your background the real sky does not account for. That is your gradient, and that is what gets subtracted. Nebulosity is in the reference too, so it is absorbed by the \(b\,B_r\) term and comes through untouched.

When to use which. ADBE is offline, unconditional, and right for ordinary vignetting and smooth light pollution on a sparse field. Reach for SRGC when the field has real large-scale structure you are afraid of losing — IFN, cirrus, a big nebula filling the frame, or anything where ADBE's result looked suspiciously flat.

2. Using the tool

2.1 Before you start

SRGC is for linear data. It models your gradient as something added to the sky and subtracts it, which is only true while the data is still linear. Once an image has been stretched — and that could be any combination of autostretch, curves, hyperbolic tweaks, masked stretching, local contrast — the gradient has been bent by whatever transfer function you applied, and no additive model describes it any more. There is also no way for the tool to invert a stretch it did not perform. On stretched data, use ordinary ABE instead.

The image must be plate-solved: the reference is fetched and aligned by sky coordinates, so without a WCS there is nothing to look up. If the image has no solution SRGC offers to run the plate solver for you. With no pointing in the header that falls back to a blind solve, which searches the quad index and can take a few minutes — so it always asks first and never starts one on its own.

Your own image — the dual-scope case

If you run two scopes on one mount, the wide one is very likely a better reference than any survey: it saw the same sky, on the same night, through the same light pollution and the same airglow. A survey tells you where real nebulosity is. A simultaneous wide frame tells you that and what the sky was doing at the time.

Choose it from the list of open images, or load a file directly. Two requirements:

  • It must cover your whole field. A narrower reference fails the coverage check rather than quietly fitting against nothing.
  • It must be plate-solved — SRGC offers to solve it for you if it is not.
The one real trap. Your reference must not carry the same gradient. If both frames tilt the same way, \(b\) absorbs the tilt and the residual is empty — SRGC will report that it removed almost nothing. That is not a wrong answer, it is an honest one, and the reference share figure (§3.6) tells you when it has happened.

3. Technical details

What follows is the method rather than the interface. None of it is needed to use the tool.

3.1 Scale

The reference is fetched and both backgrounds are modelled at reduced resolution, 1024 px on the long side by default. This is not a shortcut. A gradient is by definition a low-spatial-frequency field, and the degeneracy this tool exists to break lives only at large scales. Working small also keeps the fit well conditioned and the download small. The modelled gradient is upscaled back to full resolution before it is subtracted.

3.2 Getting the reference

Every survey here is published as a HiPS (IVOA Hierarchical Progressive Survey) — the sky tiled into HEALPix cells at a pyramid of resolutions. SRGC reads the static tile trees directly: it maps each output pixel to a HEALPix index, fetches the tiles that cover the field in parallel, and samples them onto your WCS. It does not depend on a reprojection service.

Each survey carries several mirror URLs, tried in order, leading with a non-CDS host wherever one exists. A failed route is treated by kind: an HTTP 404 retires that one path, because a mirror may carry one band and not another; a connection timeout retires the whole host, because every further route on it would time out too. A TCP pre-flight settles an unreachable host in a couple of seconds rather than waiting out the operating system's connect timeout.

A fetched reference is cached for the session, keyed on the survey, the work resolution and your image's pointing and scale. Changing degree, samples, patch size, exclusion, protect k or strength and re-running therefore costs no download at all — those are exactly the knobs worth re-running.

3.3 One set of sample points, for both models

This is the difference between a reference-based correction that works and one that quietly eats nebulosity.

Modelling the two backgrounds independently lets each chase structure in its own way — different noise, different resolution, different star content. Since the fit downstream is \(B_t \approx a + b\,B_r\), any structure one model follows and the other does not lands in the residual and is subtracted as "gradient". Sampling both at the same sky positions makes those errors common-mode, and common-mode error is precisely what the \(b\,B_r\) term exists to absorb.

3.4 The survey decides where background is

Sample points are chosen on

M = \max\left(\,\mathrm{norm}(B_r)\,,\ \mathrm{norm}(\mathrm{highpass}^{+}(I_t))\,\right)

The reference supplies the diffuse-structure veto, and your frame contributes only its high-pass: stars, trails, sharp artefacts.

Your own brightness deliberately gets no vote on whether a location is background. The target is the frame with the gradient in it — that is the entire premise — so treating a bright patch of light pollution as "not background" would starve the fit on the bright side of the gradient and bias the model toward the dim corner. It is also self-defeating: the gradient is the quantity being measured, so declining to sample where it is strong is declining to measure it. A high-pass is blind to a smooth gradient by construction, so a point sitting in the brightest corner of your light pollution is a perfectly good background sample, while a point on a star is not.

On top of that, two hard vetoes are applied to the reference: the brightest exclude% of covered sky, and a median + k·MAD signal mask, dilated and blurred. Both are smoothed at the patch scale first and have their interior holes filled — a dust lane inside a galaxy is dimmer than the sky outside it, so on a raw map it passes a brightness test and acts as a local minimum that the sampler walks straight into. Filling holes is what stops a point landing between M31's dust lanes. If structure dominates the frame the thresholds are relaxed until enough sky is samplable, and the relaxation is reported rather than hidden.

3.5 The fit

Per channel, sigma-clipped least squares for \(B_t \approx a + b\,B_r\), iterated with a MAD-based scale:

\sigma = 1.4826\,\mathrm{MAD}(r)\,,\qquad \mathrm{keep}: |r - \mathrm{med}(r)| < 2.5\,\sigma

Clipping matters more than usual here. Anything your frame has that the reference does not — a satellite trail, a reflection, a processing artefact, a galaxy the survey is too shallow to show — would otherwise tilt the fit, and a tilted fit becomes a gradient that gets subtracted. Clipping removes those before they can.

The fit runs over the whole covered frame, including the vetoed region. Restricting it to sample-constrained pixels looks more principled and measures worse: on a controlled test \(b\) fell from 0.122 to 0.081 against a known truth of 0.129, and recovery correlation dropped from 0.983 to 0.936. Two reasons. The vetoed region is not invented data — both backgrounds there are smooth predictions from the same points through the same kernel, so their extrapolation errors are correlated and cancel in a linear fit. And excluding it throws away the high-\(B_r\) end of the range, which is the leverage that determines \(b\) at all.

Colour data is fitted per channel. Light pollution is strongly colour-selective, so a red sky and a blue sky need to be explained by red and blue structure rather than by one grey average. Against a mono reference each channel still solves its own \((a, b)\) — the structure is assumed to have the same shape in every channel and a different amplitude, which is an approximation, but a far better one than no reference at all.

3.6 Units, stretches and why nothing needs rescaling

A survey cutout and your frame are in completely unrelated units — a DSS2 plate arrives as roughly 1100–20000 counts against your 0–1 floats — which raises the obvious worry that the two sides of the fit are not comparable. They are, and the fit form is the reason. Because it solves \( B_t \approx a + b\,B_r \), any linear rescaling of either side is absorbed exactly:

  • Scale your image by \( s \) and the fit returns \( a s \) and \( b s \), so the gradient comes back as \( s \cdot G \). Divide by \( s \) and you have exactly what you started with.
  • Scale the reference by \( p \) (plus any offset \( q \)) and \( b \) simply comes back as \( b/p \), with \( a \) absorbing the offset. \( a + b\,B_r \) is unchanged.

The sigma clipping does not break this either, because its threshold is MAD-based and so scales with the data. Measured: a target or reference rescaled by \( 10^4 \) changes the recovered gradient by about \( 10^{-8} \), which is float32 round-off and not a difference. So matching the two images' scales before the fit, and undoing it afterwards, is provably a no-op — and it is worse than neutral if done carelessly: rescaling a small signal onto a large pedestal cost 0.18% of the gradient span to float32 cancellation in the same test.

What the fit cannot absorb is curvature — a reference that encodes brightness non-linearly, as a log-stretched 8-bit composite does. In practice this costs very little, for a structural reason: the fit runs on background models, not raw pixels, and a background spans a narrow range by construction. Any smooth monotone curve is close to its own tangent over a narrow range, and a tangent is exactly what \( a + b\,B_r \) fits. On a real DSS2 fetch the reference background spanned 2.2% of its own sky level, which puts the second-order term of a log at about 1.1% of the reference term — and that term explained 31% of the gradient, so roughly 0.35% of the correction. Swapping a linear reference for a log, asinh, gamma or 8-bit-quantised one changed recovery by 0.01 percentage points in a controlled test.

The tool therefore does not rescale anything. It reports instead: the Survey reference tab names the format it fetched, how that tree encodes brightness (linear, log, or high-passed) and whether it can resolve a gradient at all — see §3.7.

3.7 Can the reference resolve your gradient?

Separate question from §3.8, and not covered by it. A reference quantised so coarsely that the sky sits on one or two levels can still produce a perfectly healthy \( b \) — fitted to a staircase. FITS tiles are preferred wherever a tree publishes them, but some trees are 8-bit only, so the resolution is measured directly from the data: the quantisation step is found from the gaps between distinct values, and the modelled background is reported in units of that step.

Noise decides how much that costs. If the per-pixel scatter is wider than one step, sky pixels straddle several levels and averaging a sample patch recovers structure far finer than the step — the quantisation is dithered. If the scatter is narrower, every sky pixel reads the same integer and the structure is simply gone. Four verdicts follow:

VerdictMeans
ample32+ steps, or 8+ steps with dithering. Nothing to think about.
coarse8 or more steps but undithered. The gradient's shape is described; its amplitude is described in that many discrete steps. Prefer a FITS tree if one covers the field.
coarse-ditheredFewer than 8 steps, but noise wider than a step. Patch averaging recovers sub-step structure — shape usable, amplitude soft.
pinnedFewer than 8 steps and undithered. The reference cannot resolve your gradient. Flagged with a warning on the run summary.

Measured on M81 with a 256 px work grid: the DSS2 red FITS tree gave a background spanning 91 quantisation steps with noise 48× the step (ample), while CDS's 8-bit DSS2 colour composite gave 8.5 steps with noise 0.88× the step (coarse) on the same field. Both are usable; only one of them is comfortable.

This is measured from the pixels rather than inferred from the tile format, so it also covers a reference you supply yourself — which is the case where nobody knows what the data has been through.

3.8 Is the reference actually doing anything?

The run summary splits the background structure between the two components that describe it. Write \( E \) for the amplitude the reference accounted for and \( R \) for what was left over — your gradient:

E = |b| \cdot \mathrm{span}(B_r)\,,\qquad R = \mathrm{span}(G)\,,\qquad \mathrm{share} = \frac{E}{E + R}

So the survey's share and yours sum to 100%, and neither can exceed it.

Earlier versions divided \( E \) by \( R \) alone, which could report a reference explaining 164% of the gradient. That was not a display bug but a real one, and the reason is worth knowing: spans do not add. \( \mathrm{span}(X + Y) \) equals \( \mathrm{span}(X) + \mathrm{span}(Y) \) only when \( X \) and \( Y \) are perfectly correlated, and a fitted component and its residual generally are not — so \( E \) can exceed \( R \) with both being correct measurements of their own component. The ratio of one to the other is then not a fraction of anything. For a least-squares fit the exact orthogonal decomposition is in quadrature, \( E^2/(E^2 + R^2) \); the linear form is used here because these spans are robust percentile measures rather than variances (so exact additivity is unavailable either way), and because in the small-\( E \) regime where the warning fires \( E/(E+R) \) tends to \( E/R \), which keeps the 5% trip point calibrated where it already was. Quadrature would have moved it by about a factor of four.

This is the honest self-check, and it is worth reading every time. With a strict veto the reference background can come out nearly flat, \(b\,B_r\) collapses toward a constant, and the method quietly degenerates into ADBE with a survey-derived exclusion mask. That is still a useful tool — but it is not reference-based correction, and the difference should be visible rather than assumed. A survey share near zero means one of:

  • the field genuinely has no large-scale structure, so there was nothing to attribute and ADBE would have done just as well;
  • the only structure present got vetoed as a bright object;
  • or your reference carries the same gradient as the target — the dual-scope trap from §2.2.

3.9 Subtraction

The correction is additive, always. The premise is that what the reference fails to explain is additive sky, so dividing it out would be the wrong operator. The gradient is median-centred, scaled by Strength, subtracted, and the original median restored; the result is then rescaled if needed so nothing clips at either end.

3.10 Coverage, and what the failures mean

Pixels outside the survey footprint come back non-finite and are carried through honestly. A pixel is usable only where every reference channel has data, so one channel's footprint edge cannot silently fit against a hole in another. Below 25% coverage the run stops, and the message distinguishes the cases, because they have very different fixes:

  • Partial coverage — the field runs off the edge of the survey. NSNS stops at dec −16°; the DSS2 options are all-sky.
  • Zero usable pixels — almost always a rejected or misparsed request rather than a footprint miss, since a genuine miss on a partially covered survey returns a mix.
  • A constant reference — the cutout arrived carrying no sky structure at all. A server or request problem, not a coverage one.

3.11 Notes

  • Both background models are fitted in a linear domain. The relation being fitted is linear, so a nonlinear display stretch between the two sides of it would be wrong.
  • The preview renders at reduced scale with the rendered buffers cached, so flicking Before/After or dragging Strength is immediate. Apply always runs on the full-resolution image — nothing committed depends on the preview path.
  • Apply is idempotent. Previews and Apply both work from the snapshot taken when the model was built, so applying twice recommits the same pixels rather than correcting twice.
  • The grip at the bottom-left drags out a shortcut carrying the current settings; dropped on an image it runs headlessly, and right-click → Edit preset opens a form for the same parameters. A preset always records a survey: a dual-scope reference is one array in one session, and there is no name a later run could resolve back to it.
  • Scripting: ctx.run_command('srgc', {'degree': 2, 'strength': 80}). The headless path never starts a blind plate solve — solve the image first, or use the dialog.
