Stellar Alignment

Register one image onto another's pixel grid — using stars, plate solutions, or both — the engine behind Stacking Suite, Dither Analysis, Exoplanet Hunter, and every other SASpro tool that needs frames in the same coordinate system.

The quiet workhorse. This tool solves the geometric problem of taking a target image and warping it so every pixel sees the same patch of sky as the corresponding pixel in a reference image. Standalone it's a two-image dialog with a preview; under the hood it's the same code that stacks hundreds of light frames in Stacking Suite, that measures per-frame drift in Dither Analysis, that locks a target star in place across a time-series in Exoplanet Hunter, and that solves panel-to-panel geometry in Mosaic Master. Three alignment methods (Stellar, WCS/SIP, WCS→Stellar refinement) handle everything from "two frames of the same scope on the same night" to "same object through two different telescopes with different FOVs and a meridian flip in between".

1. Picking a source and target

The two top boxes each hold a selector:

  • Source Image (Reference) — the image whose pixel grid everything else gets aligned onto. The output image inherits its dimensions and WCS.
  • Target Image (To be Aligned) — the image that gets warped. The output is a warped copy of this image, same shape as the source.

Each box offers From File (open a FITS or image file) or From View (pick any open SASpro document from the dropdown). Click Refresh next to a view dropdown if you've opened new images since the dialog launched. Source and target can mix freely — file-against-view, view-against-view, file-against-file.

2. The three alignment methods

The Method dropdown at the top of the Transform / Distortion box picks the alignment strategy:

MethodHow it worksUse it when
Stellar (star matching)Detects stars in both frames, matches them by triangle invariants, solves for the transform. The classical approach, implemented via astroalign.Both frames come from the same scope at (near) the same scale and orientation. Fast, no plate solve needed. Standard choice for stacking light frames from one session.
WCS / SIP (plate solve, no stars)Uses each image's plate-solved WCS (including SIP distortion) to reproject the target onto the reference's pixel grid. No star detection — every pixel's position is computed from the astrometric solution.Arbitrary scale, rotation, flip, or FOV difference. Both images must be plate-solved. Needed for cross-instrument alignment, mosaic prep, or any case where star matching would fail due to a dramatically different field of view.
WCS → Stellar refinementWCS reprojection first (gets both onto the same grid), then a star-matching pass refines any residual sub-pixel offset. The best-of-both method.Cross-instrument work where you want sub-pixel accuracy. Also the right pick when the plate solutions are good but you want to tighten the final alignment to the sub-pixel level that star matching provides.
Which to pick in practice. If your frames are from one scope on one night, use Stellar — it's fast and the plate solutions aren't needed. If you're combining frames from different telescopes, different cameras, before and after a meridian flip, or anything with scale/rotation disagreement, use WCS → Stellar refinement — the WCS step handles the gross geometry, and the stellar refinement pins down the final pixel. Pure WCS/SIP alone is for the rare case where you have no bright stars to match (deep narrowband with a tight field, say) but you do have plate solutions.

3. Check WCS and Trial Detect

Two small buttons let you verify the inputs before committing to a long alignment job:

Check WCS — reports whether the current source and target carry usable plate solutions. Green ✓ means a WCS with usable celestial coordinates was found; yellow ⚠ means no plate solve. For the WCS and WCS→Stellar methods, both frames need the ✓.
🔍 Trial Detect — runs star detection on both frames with the current detection sigma threshold and reports how many stars each has. Green ✓ means a healthy count; yellow ⚠ means too few (lower the threshold), too many (raise it), or no detections at all. Great for calibrating detection sigma before a stacking run.

Both buttons populate inline status labels — they never pop a modal — so you can tweak settings and re-check freely.

4. Transform models

Below the method, the Model dropdown picks the mathematical form of the final transform:

ModelDegrees of freedomCaptures
Affine (fast)6Translation, rotation, scale (x and y independently), and shear. The default — fits almost every real-world case between two frames on the same mount.
Homography (projective)8Affine plus perspective (keystone). Useful when the two images were taken with different optical axis tilt, or for correcting slight focal-plane misalignment.
Polynomial (order 3)Many (fit to inlier residuals)Nonlinear optical distortion on top of a base affine or homography. For very wide fields where coma, field curvature, or vignetting-induced distortion create curved rather than straight residuals.
Polynomial (order 4)MoreSame, but higher-order terms. Only when a 3rd-order polynomial still leaves systematic residuals. Can over-fit noise if detection is sparse.

Polynomial models always build on top of a base affine or homography — the polynomial fits only the residual correction after the linear model is applied. This two-pass structure gives much better stability than trying to fit a pure polynomial from scratch.

5. Detection and matching parameters

Max control points — upper bound on the number of star matches used to fit the transform. 250 is the default; 500-1000 helps on very wide fields with many stars, 100 is enough for simple affine fits.
Solve downsample — the solve runs on a factor-N-downsampled grid for speed, then the result is lifted back to full resolution. Default 3; raise to 2 (or 1) if the solver is bimodal between meridian-flipped frames.
Homography RANSAC reprojection (px) — the inlier threshold when fitting homography or polynomial residuals. Default 3.0 px; raise if your star PSFs are large, lower for sharp sampling.
Detection threshold (σ) — how many sigma above background a star must stand to be detected. Default 12; lower to 5-8 on sparse fields, raise to 20+ on crowded ones. Use Trial Detect to calibrate.
Detection settings are shared with Stacking Suite. The dialog shows this reminder because the solve parameters here save to the same user preference keys that Stacking Suite reads from — once you've tuned them for your rig in either tool, both apply the same settings. The common tuning path is: run Trial Detect in this dialog, pick a σ that gives you a few hundred stars on your typical frame, then those settings carry straight into your next stacking job without re-doing the calibration.

6. Running and inspecting

Run Alignment kicks the job off. Status updates stream to the left panel. When it finishes, the aligned result appears in the right-panel preview. Use AutoStretch: ON/OFF to toggle a simple percentile stretch on the preview — doesn't modify the data, just helps you see the low-contrast detail.

For Affine or Homography alignments, a Transformation Matrix Details popup shows the full matrix and derived parameters: translation (tx, ty), scale (x, y), rotation angle, and shear. When the alignment ran as WCS→Stellar refinement, the dialog notes that the matrix shown is only the residual star-refinement delta on top of the (much larger) WCS reprojection.

8. Workflow recipes

Standard two-session merge. Target image = tonight's new frame, Source = your master integration. Method: Stellar. Model: Affine. Trial Detect to confirm both have 100+ stars. Run Alignment. Create New View. You now have the new session's frame on the exact same pixel grid as your running stack — ready to add to the master in whatever integration tool you prefer.
Combining a different scope's data. Target = narrowband frame from your refractor, Source = broadband integration from your astrograph. Both plate-solved. Method: WCS → Stellar refinement. Model: Affine. The WCS stage handles the different focal lengths and orientations; the stellar refinement step fine-tunes the pixel accuracy for a clean overlay. Create New View, then combine with the broadband data in a channel compositor.
Aligning before and after a meridian flip. Target = post-flip frame, Source = pre-flip reference. Method: WCS → Stellar refinement (needed because post-flip the frame is rotated 180°; pure stellar matching can struggle at that extreme). If both are plate-solved, this handles it in one pass; if not, plate-solve both first (Plate Solver → unwarp if needed) and come back.
Wide-field with corner distortion. Target = any frame from a fast astrograph (f/2-f/4) or camera lens, Source = your reference. Stars at the frame edges won't fit a pure affine. Method: Stellar. Model: Polynomial (order 3). Max control points: 500+. The affine base captures the main geometry; the polynomial fits the residual edge distortion. If edge residuals remain, try order 4.
Calibrating detection σ for a stacking run. Before you launch a big stacking job, open this dialog on your reference frame as both source and target (a self-alignment is a nonsensical operation but it exercises detection without actually running the align). Trial Detect reports exactly how many stars your current σ catches. Settle on a value that gives you a few hundred to a few thousand stars, close the dialog, launch stacking — the setting is already shared.

9. Headless / shortcut use

The tool integrates with SASpro's drag-grip shortcut system via a command ID of star_alignment. A preset payload has this shape:

{ "reference": {"type": "view_name", "name": "Master"}, "overwrite": false, "downsample": 2, "title_suffix": "Aligned" }

Reference types supported:

  • {"type": "active"} — use whatever document is active when the drop happens.
  • {"type": "view_name", "name": "..."} — match by visible document title.
  • {"type": "view_ptr", "doc_ptr": 1234} — exact document pointer (for round-trippable shortcuts).
  • {"type": "file", "path": "/abs/path.fits"} — load the reference from disk.

Dropping the preset onto a target view runs the alignment headlessly — detect stars, solve the transform, warp, deliver — with no dialog. When overwrite is true the target doc is replaced in place; otherwise a new view is created. The default behavior across SASpro tools that depend on alignment (Stacking Suite, Dither, Exoplanet Hunter) is to call this engine directly rather than through the dialog, so the same math and the same tuning parameters apply everywhere.

10. Technical details

The star detection, triangle matching, RANSAC geometry fitting, downsample lift math, multi-pass refinement, and the anti-ring warp.

10.1 Star detection via SEP

Both the standalone dialog and the batch registration engine use SEP (Barbary 2016, a Python port of Source Extractor by Bertin & Arnouts 1996) for detection. The pipeline:

  1. Compute a 64×64-cell background mesh and global RMS: sep.Background(img, bw=64, bh=64).
  2. Threshold at σ · RMSbg:
    \text{threshold} = \sigma \cdot \mathrm{RMS}_{\mathrm{bg}}
  3. Extract sources via connected-component labeling with minimum area minarea.
  4. For each detected object, SEP reports flux, centroid (x, y), semi-major axis a, semi-minor axis b, and pixel count.

SEP is explicitly not thread-safe at the C level, so every call runs inside a module-level lock (_AA_LOCK). Pixel-stack size is grown lazily if the "internal pixel buffer full" error appears — on dense fields the default 1.5M pixels isn't enough.

10.2 Hot pixel rejection

Raw SEP detections include hot pixels, cosmic ray hits, and other spurious sources that would corrupt the geometric fit. Three filters are applied:

FWHM proxy — from the semi-major axis a, estimate the full-width at half-maximum assuming a Gaussian PSF:

\mathrm{FWHM} \approx 2 \sqrt{2 \ln 2} \cdot a

Reject detections where FWHM < 1.2 px. Real stars, even undersampled, have a ≥ 1.0 px; hot pixels tend to be a ~ 0.5 px.

Ellipticity — from the axis ratio:

e = 1 - b/a

Reject detections where e > 0.6. Real stars are nearly round (e < 0.3 typically). Cosmic ray streaks and satellite trails have e > 0.8.

Pixel count — require npix ≥ minarea (default 10). Belt and suspenders with the morphological filters above; sometimes SEP's connected-component bookkeeping includes very small objects that slip past the FWHM filter.

If all detections are rejected (a legitimate scenario on heavily under-sampled frames), the pipeline falls back to a size-only filter of npix ≥ minarea/2 — the alignment should never fail silently just because the hot-pixel filter was aggressive.

10.3 Uniform-grid control point selection

After hot-pixel rejection, the surviving detections are sorted by flux (brightest first) and allocated into a 4×4 or 6×6 grid of cells over the image. Each cell can hold up to max_per_cell stars (default 25); the total is capped at max_total (default 500). This gives a spatially uniform sample of bright stars rather than a flux-sorted cluster all in the brightest region of the frame.

Two quality gates on the resulting set:

Coverage — fraction of grid cells with at least one star:

\mathrm{cov} = \frac{\text{occupied cells}}{\text{total cells}} \geq 0.5

Below 0.5 triggers a log warning — the alignment may still succeed but the solution is probably biased toward one side of the frame.

Spread — require the 5th-95th percentile span of x (and y) to cover at least 35% of the image width (height):

\text{span}_x = p_{95}(x) - p_5(x) \geq f \cdot W

and at least 6 of 9 cells in a 3×3 grid occupied. Points clustered in a small region produce ill-conditioned transforms that fit the local area perfectly but fail wildly at the edges.

10.4 Astroalign triangle matching

With control-point sets in hand, astroalign (Beroiz et al. 2020) builds Delaunay triangulations of each, then matches triangles by their shape-invariant features. For a triangle with sorted side lengths d1 ≤ d2 ≤ d3:

d_1, d_2, d_3 = \text{sorted sides}
\mathcal{I} = (d_2/d_1, \; d_3/d_1)

The invariant is a 2D feature that's unchanged by translation, rotation, and uniform scale. Two triangles with the same invariant (within a tolerance) are candidate matches; multiple candidate matches generate a RANSAC vote for the global transform.

If initial detection fails (not enough triangles agree), the backoff retries with progressively stricter detection σ: 15, 25, 50, 80, 120. Each stricter pass yields fewer but higher-quality stars, which can succeed where a noise-contaminated dense set didn't.

10.5 Center-crop solve with coordinate lift

The initial astroalign solve runs not on the full reference image but on a center crop at ~1.2× the target image's dimensions. This has two benefits: the crop is faster to detect in, and it avoids the "target footprint sticks outside the reference" edge case that produces zero valid matches.

After matches are found in crop coordinates, the target-side x and y are shifted by the crop's top-left offset (x0, y0) to lift them into full-reference coordinates. The transform is then re-estimated with these lifted correspondences for maximum accuracy. If the first solve returns too few spatially-spread matches, the pipeline retries with a 3×3 grid of tiles across the reference — this gives much better coverage on frames where distortion makes a single-crop solve under-sample one quadrant.

10.6 Downsample affine lift

For performance, the solve runs on a factor-d downsampled grid. The transform returned in the downsampled coordinate system must be lifted back to full resolution. If S is the downsample scaling matrix:

S = \mathrm{diag}(1/d, 1/d, 1)

then an affine A measured in downsampled space maps to full-resolution space via conjugation:

A_{\mathrm{full}} = S^{-1} \cdot A_{\mathrm{ds}} \cdot S

and the inverse (used when applying an already-known full-resolution transform to a downsampled frame) is:

A_{\mathrm{ds}} = S \cdot A_{\mathrm{full}} \cdot S^{-1}

The same conjugation applies to homographies (3×3). Doing the solve at d=3 is roughly 9× faster than at full resolution and loses almost no accuracy for ordinary astronomical sampling — the lifted transform is still sub-pixel accurate.

10.7 Similarity projection

A similarity transform is an affine with no shear and uniform scale (rotation + uniform scale + translation only — 4 degrees of freedom). It's useful for cases where you know the geometry is physically a rigid rotation plus zoom and want to prevent spurious shear from fitting detection noise. The nearest similarity to a given 2×3 affine is found via SVD of its 2×2 linear part M:

R = U V^T, \quad s = \frac{\sigma_1 + \sigma_2}{2}

where U, V come from M = U Σ VT, R is the closest rotation (determinant corrected if needed), and s is the uniform scale (mean of the two singular values). The resulting similarity is sR with the original translation preserved. This is the operation that cleans up shear from a star-matched affine when the user has picked the Similarity model.

10.8 Anti-ring warp (Lanczos + bilinear blend)

Lanczos interpolation produces sharp, high-quality warps everywhere except around saturated stars, where its negative lobes create a visible dark ring (the "Lanczos undershoot" halo). Clipping Lanczos to a bilinear-interpolation envelope creates rosette-pattern facets around the stars from quantizing the kernel's lobes. The right solution is a blend:

  1. Compute the full-frame bilinear warp (soft, no ring).
  2. Compute the full-frame Lanczos warp (sharp, ring on bright stars).
  3. Build a bright-pixel mask from the bilinear warp using robust statistics:
    \tau = \mathrm{median}(L) + k \cdot 1.4826 \cdot \mathrm{MAD}(L)
    with k = 3.0 by default (1.4826 is the Gaussian MAD → sigma conversion).
  4. Dilate the mask by ~6 px (the Lanczos radius plus safety margin) so it covers the ring zone, not just the star core.
  5. Feather the mask edges with a 2-px-sigma Gaussian so the seam is invisible.
  6. Blend:
    I_{\mathrm{out}} = I_{\mathrm{Lanczos}} \cdot (1 - m) + I_{\mathrm{bilinear}} \cdot m

Where there's no bright star (m ≈ 0), the output is pure Lanczos — all the sharpness benefits. On and around bright stars (m ≈ 1), it's pure bilinear — no ring. The transition is smooth, imperceptible on inspection, and preserves the Lanczos quality on 99%+ of the frame.

10.9 Multi-pass refinement (batch registration)

The batch Star Registration engine (used by Stacking Suite) runs multiple refinement passes. Pass 1 solves on the original frame; subsequent passes solve on the already-partially-aligned frame, producing a small residual delta each time. The accumulated transform is updated by matrix composition:

T_{\mathrm{new}} = T_{\mathrm{delta}} \cdot T_{\mathrm{prev}}

Convergence is declared when the maximum delta shift across all frames falls below a tolerance (default 0.2 px):

\max_i \|T_i^{(k)} - T_i^{(k-1)}\| < \varepsilon

Frames that have already converged are skipped in later passes, concentrating work on the stragglers. Default is 3 passes maximum; in practice most frames converge after pass 2.

10.10 WCS reprojection pipeline

For the WCS and WCS→Stellar methods, the target image is reprojected onto the source grid via a two-step projection: for every output pixel (x, y) in the source grid, the source WCS forward-projects to a sky position (α, δ), then the target WCS inverse-projects back to a target pixel location (x', y'), where the image is sampled. This uses astropy's all_pix2world and all_world2pix, which honor the full SIP distortion polynomial on both ends.

Tiled processing: the output grid is swept in 512×512 tiles rather than one monolithic allocation, giving progress feedback and bounded memory. A round-trip check — forward through the target WCS, back through the source WCS, compare to the original coordinate — rejects pixels where the SIP inverse iteration diverged, replacing them with the no-data fill value. Rejection count is logged.

10.11 Polynomial residual warp

When Polynomial (order 3 or 4) is selected, two warps are chained. The first applies the base affine or homography to get the target image onto an approximately-correct grid. The second is a polynomial correction applied via skimage.transform.warp with an inverse_map callable: for each output pixel, compute its normalized location, evaluate the polynomial to get its source location in the base-warped image, and sample. The polynomial is estimated from inlier matches (those within RANSAC threshold of the base model's prediction), normalized to the [0, 1] domain for numerical conditioning. Points per channel are matched between the color stripes to keep RGB alignment identical.

10.12 Parallelism

Batch registration dispatches per-frame solves across a process pool (ProcessPoolExecutor) on native (non-frozen) builds and spawn-aware processes on PyInstaller-frozen builds (guarded by freeze_support() in the entry point to catch worker re-execs). Each worker caps BLAS and OpenCV thread counts to 1 so N frames × M internal cores doesn't oversubscribe the CPU. The finalize pass (full-resolution warp + save) uses a smaller worker pool but allows each worker's OpenCV to use multiple threads — the trade-off between number of concurrent workers and threads-per-worker is scaled by core count.

When process pool initialization fails (common on mixed-env Windows installations where child workers die on NumPy/SciPy import), the engine falls back to a thread pool so registration still completes. The thread fallback serializes astroalign calls through the global _AA_LOCK rather than parallelizing them.

10.13 Drizzle self-description stamp

Each aligned frame's FITS header carries a set of SASDZ* keywords that let the drizzle integrator reconstruct the frame's transform without needing the .sasd sidecar file. SASDZKND stores the transform kind ("affine", "homography", "poly3", "poly4"); SASDZRFH and SASDZRFW give the reference grid dimensions; SASDZORG gives the source basename; and for affine/homography, SASDZNR, SASDZNC, and SASDZ00 through SASDZ11 flatten the matrix row-major into individual FITS cards (which can only hold 8-character keyword names). Polynomial frames carry only the kind and reference dimensions, since their transforms are dense coordinate maps rather than small matrices — the drizzle integrator treats these as already-warped and deposits them on an identity canvas.
